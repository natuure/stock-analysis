# 종목스크리닝

/종목서칭(일봉 이동평균 정배열 스크리닝) 결과를 업종별로 분류해 **주 1회** MongoDB에 저장합니다. 웹앱 "종목스크리닝" 탭이 이 데이터로 주차별 종목 수 추이와 업종 추이를 보여줍니다.

## 저장 주차 규칙
한 주는 **금요일에 끝난 것**으로 봅니다 (`종목스크리닝.py`가 자동 계산).
- 금·토·일에 실행 → 이번 주 주차로 저장 (예: 10/31 토 → W44)
- 월~목에 실행 → 아직 한 주가 안 끝났으므로 직전 주차로 저장 (예: 10/29 목 → W43)
- 그 주차 데이터가 **이미 있으면** 저장하지 않고 "이미 했다"고 알립니다. (이 경우 1단계 종목서칭도 건너뛰어도 됩니다 — 아래 0단계 참고)
- 실제 종목서칭 기준일은 문서의 `asOfDate`에 따로 기록됩니다.

## 실행 절차

### 0단계 — 이미 했는지 먼저 확인 (선택, 시간 절약)
`C:\Users\USER\Desktop\Claude\주식\거래대금, 등락률 분석`에서 `python 종목스크리닝.py --dry-run`을 실행합니다. 첫 줄에 저장 대상 주차가 나오고, 이미 있으면 `[알림] 이미 W## 주차 종목스크리닝을 했습니다`가 출력되며 종료합니다 → 사용자에게 그대로 알리고 **여기서 중단**합니다.

### 1단계 — 종목서칭 실행
`/종목서칭` 스킬의 절차(가격 스냅샷 최신화 → 스크리닝)를 그대로 실행해 `주식자동매매\분석결과\종목서칭_{기준일}.csv`를 최신으로 만듭니다. `$ARGUMENTS`가 있으면 그대로 종목서칭에 넘깁니다(조건 변경). NXT 마감(20시) 이후에 실행하라는 종목서칭의 주의사항도 동일하게 적용됩니다.

### 2단계 — 분류 확인
프로젝트 폴더(`C:\Users\USER\Desktop\Claude\주식\거래대금, 등락률 분석`)에서:
```
python 종목스크리닝.py
```
- 가장 최근 `종목서칭_*.csv`를 읽어 종목을 카테고리(앱 공통 31개 업종, `저장분석.VALID_CATEGORIES`)로 분류합니다. 기존 분류(ai_analysis 최신 → rs_category_cache)가 있으면 그대로 씁니다.
- **`[분류 필요]` 목록이 나오면(종료 코드 2) 저장되지 않은 상태**입니다 → 3단계로.
- 목록이 없으면 바로 저장까지 끝납니다 → 4단계로.

### 3단계 — 미분류 종목 분류 후 재실행
1. `DATA_PIPELINE.md`의 "카테고리" 규칙과 "rs랭킹.py" 절의 표준 워크플로우를 **실제로 열어서 다시 읽고** 따릅니다 (31개 목록·정의·`기타`+`신규카테고리후보` 규칙).
2. 목록의 종목을 본업·최근 뉴스 기준으로 31개 중 하나로 분류합니다. 이름만 보고 판단하지 말고 불확실하면 WebSearch로 사업 내용을 확인합니다 (종목이 많으면 서브에이전트로 나눠도 됨).
3. 맞는 카테고리가 없으면 `기타` + `신규카테고리후보`로 두고, **새 카테고리를 목록에 추가할지는 사용자가 결정**합니다 (임의로 `VALID_CATEGORIES`를 늘리지 않음).
4. 분류 결과를 MongoDB `rs_category_cache`에 upsert합니다: `_id`=종목명, `{code, 카테고리, 신규카테고리후보?, classifiedAt: 'YYYY-MM-DD', source: 'claude_code_manual'}`. (일회성 스크립트로 처리, `.env.local`의 `MONGODB_URI` 사용)
5. `python 종목스크리닝.py`를 다시 실행해 저장합니다. 미분류가 남아 있으면 2~5를 반복합니다.

### 4단계 — 결과 보고
대화창에 다음을 출력합니다.
1. 저장된 주차(W##)와 종목서칭 기준일, 통과 종목 수 (직전 주차가 있으면 증감)
2. 업종별 분포 상위 5개 (업종, 종목 수, 비중)
3. 3단계에서 새로 분류한 종목과 카테고리 (있을 경우), `신규카테고리후보`가 생겼다면 사용자 결정이 필요하다고 명기
4. 웹앱 "종목스크리닝" 탭에서 확인할 수 있다는 안내

## 주의사항
- 이 스킬은 코드가 아니라 데이터를 만듭니다. 웹앱 반영은 MongoDB 저장 즉시 이뤄지며 별도 배포가 필요 없습니다.
- 같은 주차를 다시 저장(덮어쓰기)하는 기능은 없습니다. 잘못 저장했다면 MongoDB `stock_screening`에서 해당 `_id`(예: `2026-W44`) 문서를 삭제한 뒤 다시 실행하세요 — 삭제는 사용자 확인 후에만 합니다.
- 종목서칭 결과가 4일보다 오래됐으면 스크립트가 중단되므로 1단계를 먼저 실행하세요.
